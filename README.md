# byebye

자산·저축·지출을 바탕으로 은퇴 가능 시점을 계산하고 금융감독원 예적금 공시를 비교하는 독립 웹 앱입니다.
`tkddls8848/quotation`의 FIRE 기능에서 분리했습니다. 다른 저장소나 견적서·문서 변환 엔진 없이 빌드됩니다.

화면은 네이버 WORKS의 드라이브 구성을 참고한 WORKSHEET 업무 문서 UI입니다. [디자인과 미리보기](design/README.md)에서 확인할 수 있습니다.

## 구성

- `src/`: FIRE 계산, 입력 탭, 항상 표시되는 자산 추이 그래프, 예적금 비교 화면, 결과 공유 링크
- `worker/`: `/api/fire/products` 금융감독원 API 중계, 링크 미리보기 꼬리표 주입, `robots.txt`·`sitemap.xml`
- `public/`: 정적 응답 보안 헤더, 안내 문서, 아이콘과 미리보기 그림
- `index.html`: 자바스크립트 없이도 읽히는 소개 글과 구조화 데이터(JSON-LD), 화면이 붙기 전에 보이는 껍데기
- `wrangler.jsonc`: Cloudflare Worker 및 정적 자산 설정

## 개발 및 검증

Node.js 22.12 이상을 사용합니다.

```sh
npm ci
npm run dev
npm test
npm run check
```

API까지 포함해 확인하려면 `npm run worker:dev`를 사용합니다. Vite 개발 서버의 `/api/` 요청은 로컬 Worker의 8787 포트로 전달됩니다.
바인딩을 바꾼 뒤에는 `npm run cf:types`로 `worker-configuration.d.ts`를 다시 생성합니다.

## Cloudflare 배포

```sh
npm run deploy
```

GitHub 저장소와 Worker 모두 `byebye`이며, 배포 주소는 `https://byebye.tkddls8848.workers.dev/`입니다.
Worker 이름이 곧 주소의 앞 칸이라 바꾸면 주소가 따라 바뀝니다. 바꾼 이름으로 배포하면 **새 Worker가 생기고**
옛 이름의 Worker와 그 주소는 지울 때까지 그대로 살아 있습니다.
시크릿과 사용자 환경 변수는 저장소에 넣지 않습니다. `keep_vars: true`로 대시보드에서 직접 설정한 변수를 재배포 때 유지합니다.

Cloudflare **Workers & Pages → byebye → Settings → Variables and Secrets**에서 다음 항목을 직접 설정하세요.
Worker 이름을 바꾸면 여기에 넣어 둔 값은 따라오지 않습니다 — 새 이름으로 처음 배포한 뒤 다시 넣어야 합니다.

| 종류 | 이름 | 용도 |
| --- | --- | --- |
| Secret | `FSS_API_KEY` | 금융감독원 금융상품 통합 비교공시 OpenAPI 인증키 |

현재 코드가 요구하는 일반 환경 변수는 없습니다. `ASSETS`는 배포 때 자동으로 연결되는 정적 자산 바인딩입니다.
키를 넣기 전에도 계산기와 그래프는 동작하며, 상품 조회만 인증키 미설정 안내와 HTTP 503을 반환합니다.
로컬 API 개발용 키는 Git에서 제외되는 `.dev.vars`에 넣습니다.

GitHub 자동 검증은 `.github/workflows/ci.yml`에서 실행합니다.
Cloudflare에서 GitHub 자동 배포를 연결할 경우 저장소 루트 `/`, 빌드 명령 `npm run build`, 배포 명령 `npx wrangler deploy`를 사용합니다.

참고: [Worker 이름·변수 설정](https://developers.cloudflare.com/workers/wrangler/configuration/), [API 우선 라우팅](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/).

## 화면 껍데기

`src/workspace.ts`가 문서 탐색과 화면 전환을 담당하고, `src/workspace.css`가 반응형 레이아웃을 정의합니다.

- 상단 문서 검색과 왼쪽 탐색 메뉴에서 분석 시트·비교 자료·산출 기준을 열 수 있습니다.
- 제목은 `중장기 운영 계획`이며, 입력값 변경 시 계산 결과와 그래프가 갱신됩니다.
- `Esc` 또는 목록 보기를 누르면 계산 화면 전체를 숨기고 문서 목록을 표시합니다. 다른 브라우저 탭으로 이동할 때도 자동 전환됩니다.
- 목록 상태는 같은 탭의 새로고침에도 유지됩니다. 시트를 다시 열면 입력값을 복원합니다.
- 모바일에서는 메뉴 버튼으로 탐색 메뉴를 열고 입력과 결과를 한 열로 표시합니다.
- 금융감독원 예적금 비교, 가입기간에 따른 계산, 결과 공유 기능을 유지합니다. 공유 주소는 분석 시트의 문서 링크 공유를 펼쳐 확인합니다.

## 공유와 검색 노출

### 예적금 상품 조건 적용

상품 비교에서 **조건 확인·적용 → 은퇴 계산에 적용**을 선택합니다. 가입 대상·한도·우대조건 등 공시 내용을 확인하고, 기본금리 또는 우대조건 충족 가정을 선택할 수 있습니다. 예금과 적금은 각각 한 상품씩 적용합니다.

- 예금은 현재 예금 자산 중 선택한 금액을 예치합니다. 적금은 기존 월 저축액의 적금 배분 안에서 매월 같은 금액을 납입합니다. 기존 적금 잔액은 별도로 유지합니다.
- 선택한 가입기간에 **한 번만** 적용합니다. 단리·월복리와 회차별 적금 이자를 계산하고 만기에 원금과 세후 이자를 해당 자산군으로 돌려놓습니다. 만기 이후에는 기존 입력 수익률을 적용하며 자동 재가입하지 않습니다.
- 중도해지 이율은 해석하지 않습니다. 목표 은퇴 전에 만기가 도래해야 하며, 은퇴 가능 시점도 적용 상품의 만기 이후부터 탐색합니다. 만기 전 자산에는 아직 지급되지 않은 상품 이자를 포함하지 않습니다.
- 예치 자산·월 저축 배분·공시 최고한도를 초과하면 적용할 수 없습니다. 이후 입력 변경으로 조건이 맞지 않으면 해당 상품을 계산에서 제외하고 사유를 표시합니다. 문장으로 제공되는 추가 한도와 가입·우대조건은 사용자가 확인합니다.
- 적용 전후 은퇴자산을 비교하고 개별 상품 적용을 해제할 수 있습니다. 선택은 브라우저에 저장됩니다. 공유 링크에는 상품명 대신 계산 조건을 담아 같은 결과를 복원하며, 재가입 가능 여부나 현재 판매 여부를 보장하지 않습니다.

상품 계산은 `src/product-plan.ts`, `src/model.ts`에 있으며, 검산 사례는 `src/product-plan.test.ts`에 있습니다.

### 결과 공유 링크

결과 아래의 **링크 복사**를 누르면 입력값을 담은 주소(`/?s=...`)가 만들어집니다. 담는 형식은 `src/share.ts` 에 있습니다.

- 입력 마흔한 개를 정해진 순서로 `_` 로 이어 붙입니다. 기본값 기준 130자 안팎입니다.
- 맨 앞이 형식 번호입니다. **항목은 뒤에만 더하십시오.** 중간에 끼우면 이미 퍼진 링크가 다른 뜻으로 읽힙니다.
- 상품 조건이 있으면 형식 2로 예금·적금별 금액, 기간, 금리, 복리 여부, 우대 여부, 한도를 추가합니다. 기존 형식 1 링크도 계속 지원합니다.
- 읽을 때 항목마다 범위를 보고, 벗어나면 그 항목만 기본값으로 둡니다. 손으로 고친 주소가 들어와도 화면이 무너지지 않습니다.

공유 링크를 열면 그 값이 화면에 올라오고, 값을 하나라도 고치면 주소에서 `?s=` 가 사라집니다. 남의 숫자를 내 것처럼 다시 퍼뜨리지 않도록 하기 위해서입니다.

### 링크 미리보기

카카오톡·슬랙·트위터의 수집기는 자바스크립트를 돌리지 않으므로, `worker/meta.ts` 가 HTML 이 나가기 전에 `<!--meta:start-->` 와 `<!--meta:end-->` 사이를 갈아 끼웁니다.

- 공유 링크에 결과가 담겨 있으면 `"41세부터 은퇴 가능 · FIRE 계산기"` 처럼 그 결과의 글귀와 판정별 그림(`og-possible|late|impossible.png`)으로 바꿉니다.
- 주소는 요청에서 읽습니다. `*.workers.dev` 로 열든 제 도메인을 붙이든 canonical 과 `og:url` 이 저절로 맞습니다. **도메인을 코드에 적을 자리는 없습니다.**
- `og:url` 은 결과가 담긴 주소를, `canonical` 은 결과가 빠진 정식 주소를 가리킵니다. 눌러 들어온 사람은 그 결과를 보고, 검색엔진은 같은 쪽을 하나만 담습니다.

표식을 지우면 미리보기가 기본값으로 굳습니다. `index.html` 과 `public/guide/*.html` 을 고칠 때 함께 옮기십시오.

### 미리보기 그림 다시 만들기

`public/og*.png`(1200×630), `apple-touch-icon.png`, `icon-512.png` 는 만들어 둔 파일을 저장소에 넣어 둔 것입니다. 빌드에 붙어 있지 않으므로 문구나 색을 바꾸려면 1200×630 크기로 다시 만들어 같은 이름으로 덮어쓰면 됩니다. 크기를 바꿀 경우 `worker/meta.ts` 의 `IMAGE_SIZE` 도 함께 고칩니다.

### 안내 문서

`public/guide/` 의 정적 HTML 세 쪽이 검색으로 들어오는 길입니다. 문서를 더하면 `worker/meta.ts` 의 `SITE_PAGES` 에도 주소를 적어야 사이트맵에 올라갑니다.

### 배포 뒤에 할 일

코드 바깥의 일이라 사람이 직접 해야 합니다.

- [구글 서치콘솔](https://search.google.com/search-console)과 [네이버 서치어드바이저](https://searchadvisor.naver.com)에 사이트를 등록하고 `/sitemap.xml` 을 제출합니다.
- 커스텀 도메인을 붙입니다. `*.workers.dev` 주소는 검색 순위와 신뢰도 모두 불리합니다.
- [카카오 디벨로퍼스 도구](https://developers.kakao.com/tool/debugger/sharing)와 [페이스북 공유 디버거](https://developers.facebook.com/tools/debug/)에서 미리보기 카드가 제대로 뜨는지 확인하고 캐시를 지웁니다.

## 데이터

계산 입력은 브라우저에 저장되고 서버로 전송되지 않습니다.
**결과 공유 링크를 직접 만들 때만** 입력값이 주소에 담기며, 미리보기 카드를 만드느라 Worker 가 그 주소를 한 번 읽습니다. 읽은 값은 꼬리표를 만드는 데만 쓰고 어디에도 저장하지 않습니다. 새 배포 주소는 기존 사이트와 출처가 달라 기존 브라우저 입력값이 자동 이전되지 않습니다.
상품 공시는 금융감독원에서 가져옵니다. 실제 적용 금리·한도·우대조건은 해당 금융회사에서 확인해야 합니다.
